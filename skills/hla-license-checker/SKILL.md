# HLA License Checker

## 目的
レイヤーに重ね合わせるデータ（外部API、配信データ、背景タイル、独自データ）や組み込むライブラリについて、ライセンス・利用規約面の確認をサポートし、**レイヤー製作者が見落としがちな確認事項に気づかせる**こと。

※**HLAのデータ非複製とライセンス上の優位性**:
HLAではデータを手元にダウンロードしてローカル保存・再配布（コピーの作成）を行いません。**LaWA自身がオリジナル提供元から直接 `fetch()` して動的に描画する**ため、データの複製・再配布に伴うライセンス違反リスク（再配布禁止条項への抵触等）を原理的に回避できます。本スキルでは、この非複製モデルを前提として、直接fetch（参照利用・API利用規約・出典表記義務）に関する確認事項を整理します。

## 基本スタンス（「分からない場合は分からない」＋製作者への気づき提供）
1. **勝手な「問題なし」断定の禁止**
   - データ断片・URL文字列・ファイル名のみから、利用可否やライセンス適合性を勝手に「問題ない」と断定してはならない。
2. **不明点の率直な明示**
   - 提示された情報からライセンスや利用規約が確認できない場合は、**「分からない／判断できない」と率直に明示すること**。
3. **自律的な外部通信の禁止**
   - 利用規約ページや外部URLへエージェントが自律的にアクセスしてはならない。確認が必要な場合は、ユーザーに元データの提供元・規約テキスト・メタデータの確認を促す。

## 製作者に気づかせるべき確認観点（チェックリスト）
LaWAによる直接fetch（データコピーを作成しない参照利用）を踏まえ、以下の観点を整理して製作者に提示する。

1. **ライセンス・利用規約の種別と参照利用の許容**
   - CC BY（表示）、政府標準利用規約、自治体オープンデータ規約、独自API利用規約等のいずれに該当するか。
   - 地図上への直接fetchによる重畳表示、API経由の取得、商用/非商用利用が認められているか（データを複製・再配布しないため、再配布禁止条項には通常抵触しないが、参照・API利用条件を確認）。
2. **出典・クレジット・著作権表示の義務**
   - 出典表記や著作権表示の義務があるか。
   - 必要な場合、どこにどのように表示すべきか（S-LaWA内の専用クレジット欄 `#layer-credit` 等）。
3. **技術的・運用の利用条件（直接fetch・API利用時の制約）**
   - 直リンク（ホットリンク）の可否、レート制限（リクエスト頻度）、APIキーの要否、CORS制限の有無。
4. **個人情報・機密情報・利用制限データの有無**
   - 参照するエンドポイントに非公開情報や契約上制限のあるデータが含まれていないか。
5. **併用ライブラリ・背景タイルのライセンス**
   - S-LaWA内にLeaflet等のライブラリや外部タイルを重ね合わせる場合、それぞれのライセンス（BSD/MIT等）およびタイル配信元の利用規約（帰属表示・アクセス制限）を満たしているか。

## 出力フォーマット
```markdown
## ライセンス・利用規約 確認サポート結果

### 1. 現時点で把握できる情報 / 分からない点
- **把握できた情報**: （提示されたライセンス表記・出典情報があれば記載）
- **分からない・未確認の点**: （提示情報だけでは判断できない事項を明示）

### 2. レイヤー製作者が確認すべきチェック事項
- [ ] **元データの利用規約・ライセンス**: （確認すべき具体的な点）
- [ ] **出典・クレジット・改変表記の要否**: （S-LaWA内UI等への記載が必要か）
- [ ] **公開・共有・再配布の可否**: （ローカル利用のみか、外部公開・他コンテナ重畳を想定するか）
- [ ] **配信元・タイルの技術的利用条件**: （直リンク・ホットリンク・レート制限・認証規約等）

### 3. S-LaWA / レイヤー設計への反映提案
- （出典表記欄の設置や、規約確認後に確定すべき箇所のメモ）

### 4. 次のステップ
- ライセンス確認の整理完了後、接続元データの詳細構造調査（`hla-data-inspector`）または要件定義・設計（`hla-layer-architect`）へ引き継ぎます。
```
