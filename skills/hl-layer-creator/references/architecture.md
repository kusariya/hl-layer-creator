# HLA / HLMap アーキテクチャ

## 分散型の地図構成

HLAは、ウェブ上の独立したリソースを参照して地図を構成する。`Container.svg` は座標系や表示範囲、レイヤー参照を宣言し、各レイヤーは静的なSVGまたは必要に応じてLaWAとして動作する。

```text
Host HTML
  └─ Container.svg (地図の宣言的な構成)
      ├─ 静的SVGレイヤー
      ├─ LaWAレイヤー
      └─ 外部のSVGMap/WebApp Layerリソース
```

従来型の地図ライブラリとの大きな違いは、中央のアプリケーションがすべてのデータやレイヤーの実装を抱えるのではなく、複数の独立リソースを組み合わせられる点にある。既存のLeaflet等の資産も、要件が合いレイヤー境界内に保てるなら検討できる。特定のライブラリを一律に禁止するのではなく、親コンテナや他レイヤーとの責務境界を保つ。

## Container.svg とレイヤーの役割

- `Container.svg` は表示するレイヤーと空間参照情報を宣言する。
- 静的SVGレイヤーは、変化しない図形や既存SVGコンテンツを表現する。
- LaWAは、レイヤー固有の動的処理やUIが必要な場合に用いる。
- 地図の移動・ズーム、座標系、レイヤー境界の具体的なルールは、[仕様リファレンス](./specification.md)、[LaWA開発ガイド](./lawa_guide.md)、[ハーネス監査票](./harness_and_anti_patterns.md)で確認する。

すべてのコンテンツをLaWAにする必要はない。まず公式チュートリアルの静的レイヤーやContainer.svgの例から始め、動的処理が要件にある場合にWebApp Layerの構成を選ぶ。

## データ供給方式

リモートデータをLaWAから直接取得する方式は選択肢の一つである。ローカルファイル、事前生成したSVG/画像、キャッシュ、Webサービスなど、利用条件と運用要件に合わせた方式を選ぶ。詳細な判断は[データ供給方式と利用条件](./data_source_architecture.md)を参照する。

## 公式教材

構成の導入には[SVGMap公式チュートリアル](https://svgmap.github.io/tutorials/)を使う。基本表示、レイヤー化、タイル、ビットマップ、WebApp Layer、Webサービス、既存Layerの活用を段階的に説明している。対応する教材の選び方は[tutorial_workflow.md](./tutorial_workflow.md)を参照する。
