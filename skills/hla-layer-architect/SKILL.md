# HLA Layer Architect

## 目的
ユーザーの要望を、単一の地図アプリケーション機能としてではなく、**「独立して流通・重畳可能な分散地図レイヤー（HLAコンポーネント）」**として設計する。
（※具体的なデータ・URL・仕様が既にある場合は、接続元探し等の前工程をスキップして本スキルから直接要件定義・設計を開始できる）

## 設計原則
1. **データの非複製原則（No Data Copy / LaWAによる直接fetch）**
   - **HLAにおいて最重要の原則は、「データを手元にダウンロード（DL）してローカル保存・再配置するのではなく、LaWA自身が提供元から直接 `fetch()` してデータのコピーを作成しないこと」である。**
   - データを手元にDLしてプロジェクト内に抱え込む設計を禁止し、URLからのオンザフライ取得・描画フローとして設計する。
   - これにより、データの二重管理・陳腐化を防ぎ、常にオリジナルの最新データと同期させ、再配布禁止等のライセンス懸念を排除する。
2. **レイヤーの完全なカプセル化**
   - データ取得（fetch）、オンザフライ描画処理、専用UI（LayerUI）のすべてを該当レイヤー（S-LaWA等）配下で完結させる設計にする。
   - 親ビューア（コンテナ側・共通シェル）に特定レイヤー固有のJavaScriptやCSSを追加する設計は禁止する。
   - `appLayer` 等でLeafletを重ね合わせる構成についても、レイヤー境界内に閉じて独立性が保たれる形であれば設計対象に含める。
3. **SVGMapコア機能との責務分担**
   - レイヤーの表示/非表示切り替え、アンロード（破棄）、ズーム範囲によるカリング（`visible-min-zoom` / `visible-max-zoom`）は**SVGMapのコア機能が制御する**。レイヤー側でコアのライフサイクル制御を再発明・上書きしない。
4. **S-LaWA（LayerUI）の責務定義とライセンス確認結果の反映**
   - フィルタリング、凡例表示、データ更新、クリック時の詳細表示など、レイヤー固有の操作・描画ロジックをS-LaWA側のHTML/JSでどのように制御するかを定義する。
   - `hla-license-checker` の結果を受け、出典・クレジット表記欄の設置や、製作者が確認すべき利用条件を設計に反映する。

## 出力フォーマット
設計書として以下を出力し、`hla-layer-implementer` へ引き継ぐこと。
1. **レイヤーファイル構成案**（コンテナSVGへの記述スニペット、レイヤー本体SVG、S-LaWA用HTML/JS）
2. **データ取得・描画設計**（LaWA直接fetchによるデータ非複製フロー、ローカルXML DOM `svgImage` へのオンザフライ反映）
3. **S-LaWA UI・イベント・出典表示設計**（初期化時、地図移動/ズーム時、更新時の挙動、出典・ライセンス表記枠）
